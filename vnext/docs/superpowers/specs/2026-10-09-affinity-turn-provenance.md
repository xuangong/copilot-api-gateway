# Authenticated turn provenance

## Intent and evidence

Baseline: vNext `6b5ff39dea61fffd9645370ed19b964a5fae30a7`; reference `1d7dcd923e260e425120cca0c7a240e93720af27`. This extends, and deliberately supersedes, October 8's zero-carrier ordinary-output contract. It does not invalidate the frozen measurements; those measurements do not describe this new writer.

Reference #225 introduced per-turn authenticated upstream/model provenance, including synthetic anchors when no natural opaque value existed. #233 separated routing from item storage and added ordered inheritance for blobless Responses state. #279 distinguished absent native value from authenticated whole-synthetic-item identity. Commit a2349daca removed routing preference based solely on origin. #513/#523 established provider compatibility identity for cross-model continuation. Current source and roundtrip tests retain four-protocol issuance; only Responses currently consumes origin-only provenance for required continuation.

Sources: [#225](https://github.com/Menci/Floway/pull/225), [#233](https://github.com/Menci/Floway/pull/233), [#279](https://github.com/Menci/Floway/pull/279), [preference removal](https://github.com/Menci/Floway/commit/a2349daca7c6ffec33385bdcd26a21a68eacf219), [#513](https://github.com/Menci/Floway/issues/513), [#523](https://github.com/Menci/Floway/pull/523).

## Contracts

1. Each real assistant turn/Chat choice/Gemini candidate with a stable gateway API key and trusted actual execution identity carries authenticated provenance in its client protocol. No identity may be inferred from a public alias. No fake choice/candidate is emitted for usage-only/error output.
2. Natural opaque values remain v1 and retain their existing original bytes, companion binding, limits, compatibility and downgrade rules. Empty native strings remain native values, distinct from absent origin.
3. v2 represents origin-only metadata with authenticated target and `syntheticItem`. It carries no native value. Authentication binds wire version, API-key owner/id/secret id, source protocol and slot. Origin-only metadata deliberately does not authenticate mutable companion content: clients can aggregate streamed text and tool Parts. Natural v1 still authenticates its full companion. Unknown versions and invalid owned markers fail closed. Foreign native values remain unchanged.
4. Whole synthetic deletion requires both authenticated identity and a strict empty protocol shape. Responses uses a reasoning item with empty summary, Messages a redacted_thinking block containing only its authenticated data slot. Chat and Gemini use only a metadata slot on the real assistant message/content-bearing Part; removal preserves visible reasoning, tools, refusal, audio and other content.
5. Origin-only history does not prefer the old producer, degrade a candidate, prepare all candidates, or install an execution fence. Native state and inherited required state do use authorized candidate preparation, compatibility and the actual-execution fence. Authentication never grants authorization.
6. Responses input is scanned in order. Owned natural or origin-only state updates the provenance cursor. Blobless program/program_output/compaction/compaction_summary inherits the latest owned target. Each inherited constraint remains independently effective. A recognized foreign blob suppresses inheritance for that item but does not erase the preceding cursor. Plain text/business JSON does not alter the cursor. For context_compaction, natural v1 remains required with its existing domain; blobless context_compaction does not inherit or clear the cursor. v2 supports only the four issued shapes and rejects context_compaction slots.
7. The canonical history snapshot preserves origin markers. Candidate preparation and provider request materialization strip authenticated origin metadata before translation. Existing v1 restrictions on lossy protocol paths remain. Provenance is emitted in the final client protocol, never copied into a different authenticated domain.
8. Responses JSON/SSE/WS and persisted/private continuation share a canonical prefix ID/token. Prefix events and terminal output agree. Native IDs/call IDs remain unchanged; output indices and event sequence numbers are projected at the client boundary. Failed and incomplete turns do not save completed snapshots. Cancellation before the save barrier starts no write, and cancelled completion does not publish a reusable response/private continuation. An already-started save remains owned and may finish after cancellation; its durable record is not rolled back.
9. Ordinary text remains streaming. Added metadata has bounded per-turn/per-choice state; no whole-text buffering is introduced for the new Responses/Messages/Gemini origin anchor. Natural signed companions retain their existing bounds. No unmeasured speed or memory claim accompanies the change.

## Boundaries and alternatives

Selected: separate v2 origin metadata and v1 natural state, with ingress consumption and client-side issuance. Reusing v1 synthetic would conflate slot removal with whole-item removal and reject otherwise valid tool histories. Responses-only issuance would satisfy one current consumer but miss the uniform reference contract requested by the user. Restoring ordinary sticky selection would resurrect a withdrawn requirement.

Responses uses one independent prefix per real response. This avoids waiting for the first natural item to finish, works when native blobs arrive late, and gives blobless state a stable preceding origin. Natural opaque items still carry their own source; the additional bounded per-turn signature is an explicit tradeoff. Chat reuses a natural v1 signature when available, otherwise emits v2 at each completed real choice. Messages uses a redacted prefix. Gemini attaches origin metadata to a content-bearing Part using a bounded one-event window, with natural signatures taking precedence. It never introduces an empty Part: [Go GenAI Chat rejects that entire turn](https://github.com/googleapis/go-genai/blob/dc282483e1a68eaeb64faa9fa9877dd4a7ad1887/chats.go#L49-L80). Clients that discard metadata while aggregating text, or keep first-chunk-only function metadata despite a much later signature, remain explicit client-side limits, as in the reference. An empty Gemini candidate has no suitable carrier slot and is not fabricated into content.

At this design's original baseline, Claude Code lacked trustworthy execution capture. Its provider-native identity contract was deliberately separate, with no guessed origins. The subsequent [Claude credential lease design](2026-10-09-claude-code-credential-lease.md) supplies credential-scoped effects and actual-execution capture; see its linked implementation plan for acceptance. SDF image generation remains outside this conversational turn contract.

The adopted Responses-native `program`, `program_output`, `compaction` and `compaction_summary` items must fail explicitly before cross-protocol translation even without opaque fields, because no reversible client representation exists. Encrypted `context_compaction` and encrypted agent messages retain their existing rejection. The legacy blobless `context_compaction` form is not covered by this change and must not be described as supported. This does not promise arbitrary client-protocol switching or reconstruction of native program state in Messages/Chat/Gemini.

## Rollback and data

Land a reader-only commit before the writer. That commit accepts v1/v2, strips metadata and applies required inheritance while continuing to emit only v1 natural state. It is the usable rollback baseline for a writer-enabled release. Pre-reader binaries reject v2 history; they are not transparent rollback targets. Neither silent stripping nor downgrading owned v2 to foreign is permitted.

No schema migration or production data changes are required. Existing snapshots may contain v2 after the writer is enabled; preserve the API-key affinity secret and snapshots together in release backups. Reference raw API-key rotation preserves its serverSecret, while secret replacement makes old carrier decoding foreign; vNext intentionally has different fail-closed semantics. Do not confuse credential rotation, gateway affinity secret rotation and database restoration.
