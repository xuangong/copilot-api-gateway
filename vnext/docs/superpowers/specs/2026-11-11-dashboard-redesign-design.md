# Dashboard 现代化重设计

日期：2026-11-11
范围：`vnext/apps/dashboard`；第三期涉及 `packages/gateway/src/shared/edge/ui-pages/` 下的登录、设备授权、接入指南页面。

## 目标与约束

- 重做导航和信息架构、视觉风格两个方面。
- **硬约束：现有功能全部保留。** 页面里的布局结构、字段、按钮、文案、接口调用和权限差异保持不变；只换外框、导航、视觉规范和控件实现。
- 风格方向：Vercel 风格的清爽中性控制台（Linear / Vercel 一类）。符合 `PRODUCT.md` 的"精确、务实、沉稳"，并满足其中的无障碍要求（语义表格、带标签的控件、键盘可操作、不只靠颜色区分状态）。
- 不追随参考项目（copilot-gateway）的 Fluent UI / WinUI 实现；组件库按本产品的特点选择。

## 组件库选择

采用 shadcn/ui 的做法：Radix UI 无样式组件 + Tailwind + class-variance-authority。组件源码放进项目自己维护，不引入黑盒组件库。

理由：

- 默认外观即 Vercel 风格，与选定方向一致。
- 与现有技术栈（React 19、Tailwind 3、bun 打包）贴合，可以逐页迁移。
- 本产品的难点在复杂表单、弹窗、选择框、可搜索选择、多选、菜单、提示和 Toast；Radix 在键盘操作、焦点管理和读屏支持上可靠，替换现有自写的 `Modal`、`Select`、`Combobox`、`MultiSelect`。
- 按组件引入，体积可控。dashboard 包现为 893 KB（gzip 276 KB），内嵌进 Cloudflare Worker；预算为增加不超过 300 KB。

新增依赖：

- `@radix-ui/*`：只装用到的组件（dialog、popover、dropdown-menu、select、tabs、tooltip、switch、checkbox、toast 等）
- `class-variance-authority`、`clsx`、`tailwind-merge`
- `lucide-react`（图标）
- `cmdk`（可搜索选择）
- Geist、Geist Mono 字体

图表继续用 Chart.js，只换配色和字体。

关于上层目录 `/Volumes/Projects/CLAUDE.md` 中"禁止 shadcn/ui 和 Lucide、必须用 Fluent UI"的规则：那是 Societas 项目的规则，不适用于本仓库。本设计已向用户说明，用户同意按此方案进行。

## 一、设计规范

**颜色**

- 浅色：底色 `#ffffff` / `#fafafa`；边框 `#ebebeb` 一类的细线；文字三级 `#0a0a0a` / `#525252` / `#737373`。
- 深色：底色 `#0a0a0a` / `#111111`；边框 `#262626`；文字三级 `#ededed` / `#a1a1a1` / `#8f8f8f`。
- 第三级文字不用更浅的灰：要在底色上达到 4.5:1 的对比度。
- 强调色只保留一种：沿用紫色。
- 状态色：红（错误/危险）、黄（警告）、绿（成功/在线），总是配图标或文字。
- 去掉玻璃质感（`--glass-bg`）、噪点纹理（`body::before`）、发光边框（`glow-*`）和渐变背景。

**字体**

- 界面文字用 Geist，数字、模型名和代码用 Geist Mono；数字一律等宽对齐（`tabular-nums`）。
- 正文 13–14px；小字统一为 12px，不再混用 10px、11px。
- 替换 `page.ts` 中的 Outfit / IBM Plex Mono 字体引用和 `tailwind.config.ts` 的 `fontFamily`。

**形状与间距**

- 圆角统一 6–8px。
- 卡片只用细边框、不加阴影；弹窗、下拉、菜单才有阴影。
- 间距按 4 的倍数。

**组件**（放在 `apps/dashboard/src/ui/`）

按钮（主要、次要、幽灵、危险）、输入框、文本域、下拉选择、可搜索选择、多选、开关、复选框、分段切换、标签页、弹窗、侧边抽屉、菜单、提示、Toast、徽章、表格、空状态、页面标题区。

**主题和语言**

浅色、深色和中英文切换都保留，继续使用 `page.ts` 注入的 `toggleTheme` / `toggleLang` 和 `data-theme` 属性。

## 二、外框、侧栏和窄屏

**布局**：左边是固定侧栏，右边是内容区；内容区单独滚动。取消顶部 Tab 栏。

**侧栏（从上到下）**

1. 品牌名 Copilot Gateway。
2. 分组导航，每个页面配一个图标：

   | 分组 | 页面 | 可见性 |
   |---|---|---|
   | 观测 | 用量 `#usage`、延迟 `#latency` | 所有人 |
   | 模型 | 模型 `#models`、定价 `#pricing` | 所有人 |
   | 访问 | API Keys `#keys`、用户 `#users` | 用户仅管理员 |
   | 接入 | 上游 `#upstreams`、代理 `#proxies`、中继 `#clients` | 代理仅管理员 |

   组内一个可见页面都没有时，整组隐藏。

3. 底部固定区：
   - Agent Remote：仅在 `/api/agent-remote/config` 返回启用、且是会话登录（`ses_` 令牌）时显示，与现有条件一致。
   - 账户行（头像 + 名字）：点开是账户菜单，包含现有全部选项：设置（导出/导入，`#settings`）、共享观测、修改密码、退出；管理员标识也在这里。
   - 语言、主题两个图标按钮。

**页面标题区**

每页顶部为"分组 / 页面名"的面包屑、大标题和可选的一行说明；页面原有的主要操作按钮（如新建 Key、添加上游）放在标题右侧。

**地址和默认页**

- 沿用现有 hash 地址（`#usage`、`#keys` 等），书签和链接继续有效。
- 打开 `/dashboard` 未指定页面时，默认进入"用量"（现为第一个可见页，即"上游"）。

**窄屏**

- 宽度 < 1024px：侧栏收为只显示图标的窄栏，悬停显示页面名。
- 宽度 < 768px：侧栏隐藏，顶部为细栏（菜单按钮、当前页名、账户头像），点菜单从左侧滑出完整侧栏。
- 内容区最大宽度约 1152px（沿用现在的 `max-w-6xl`），宽屏居中。

## 三、页面迁移

**原则**：只换外观和控件，不改功能和流程。

**第一期：底座和外框**

- 先把 Tailwind 3 升级到 4，界面保持不变（11 个页面逐像素对比验证）；主题从 `tailwind.config.ts` 移进 `styles.css` 的 `@theme`。升级和新设计规范改的是同一批文件，经用户同意合在第一期的同一个提交里。
- 安装依赖；引入字体；定义新颜色、字号规范；建立 `src/ui/` 中外框要用的组件（按钮、提示、菜单、侧边抽屉）。其余组件在第二期由第一个用到它们的页面引入。
- 新侧栏；页面顶部先只放面包屑。大标题和主要操作按钮在第二期迁移各页时加上，同时去掉页面里原有的标题，避免重复。默认首页改为"用量"。
- 把现有共享样式名（`glass-card`、`btn-primary`、`btn-ghost`、`text-themed*`、`bg-surface-*`、`accent-*`、`border-themed`、`pg-*` 等）映射到新规范的值。这样第一期完成时，所有页面不改页面代码就已是新外框加新配色。
- 在浏览器里记下显得别扭的地方，留给第二期。

**第二期：逐页迁移**，每组单独提交，顺序：

1. 用量、延迟
2. API Keys
3. 上游（含上游表单）
4. 模型和测试区（聊天、图像、嵌入、决策面板）
5. 定价、用户、代理、中继、设置、Agent Remote

每页要做的事：

- 自写的 `Modal`、`Select`、`Combobox`、`MultiSelect` 换成 `src/ui/` 组件；
- 清掉写死的颜色和行内样式，统一字号和间距；
- 表格统一样式，加空状态；
- 页面主要操作挪到标题区。

全部页面迁完后，删除旧的共享样式名和旧组件。

**第三期：服务端页面**

登录、设备授权、接入指南页（`login.ts`、`device.ts`、`guide.ts`、`layout.ts`）只同步颜色和字体，结构不动。

**防止漏功能**

每组页面开工前，先从代码列出该页的功能清单（按钮、弹窗、筛选、开关、表单字段、权限差异），写进那一组的实现计划。迁移完在浏览器里按清单逐项验证：

- 管理员和普通用户；
- 浅色和深色；
- 中文和英文。

**计划拆分**

本文档覆盖整体设计。实现计划按期拆分：先写第一期计划并实现；第二期每组页面各写一份小计划，做之前再写；第三期单独一份。

## 四、测试、验证和上线

**自动测试**

- 现有 dashboard 测试必须全部通过。检查旧页面结构的测试随迁移同步更新，只改结构相关的断言，不放松行为断言。
- `src/ui/` 组件的单元测试覆盖渲染结果、变体、禁用状态和受控值。dashboard 测试用 `renderToStaticMarkup`，没有 DOM 环境，所以键盘操作（Esc 关闭、方向键选择、焦点不跑出弹窗）在浏览器验证中逐项检查，不为此新增测试依赖。
- 侧栏测试覆盖：
  - 管理员和普通用户的入口差异；
  - 组内无可见页面时整组隐藏；
  - Agent Remote 只在启用时出现；
  - 打开 `/dashboard` 时默认进入"用量"；
  - 旧 hash 地址都能打开对应页面。

**浏览器验证**

用数据库副本起临时网关，在独立 Chrome 里检查：

- 宽度 1440、900、390；
- 浅色和深色，中文和英文；
- 管理员和普通用户。

每期按功能清单逐项点验并截图。

**体积和无障碍**

- 每期记录 dashboard 包在改动前后的大小，预算为比基线多 300 KB 以内（基线 893 KB / gzip 276 KB）；超出时先查原因再继续。
- 用 Lighthouse 和键盘走查，重点检查对比度、焦点框和表单标签。

**上线**

- 每期合入前跑全量 `bun run ci:local`。
- 依赖通过腾讯镜像安装（`BUN_CONFIG_REGISTRY=https://mirrors.cloud.tencent.com/npm/`），lockfile 一起提交。
- 每期完成后先汇报和截图，用户确认后再提交、推送，并部署到本地 Docker、SSH lab 和 CFW。
