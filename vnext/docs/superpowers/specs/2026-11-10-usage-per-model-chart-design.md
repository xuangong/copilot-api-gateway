# Usage 趋势图按模型分线 — 设计

日期：2026-11-10
状态：已与用户确认设计，待评审规格
范围：仅 dashboard 前端（`apps/dashboard`），后端与 `/api/token-usage` 不变。
后续：Dashboard 整体重新设计是独立项目，另写规格；本图届时按新的设计语言再调整一次样式。

## 背景

Usage 页的趋势图按"第一个未筛选的维度"拆分曲线，顺序是 用户 > Key > 客户端 > 模型（`state/usage.ts` 中的 `chart`）。管理员选定一个人之后，图会改成按 Key 拆分；要把用户、Key、客户端都选定，才会轮到按模型拆分，所以实际上看不到每个模型的用量。

用户的诉求：选定一个人后，趋势图每个模型一条线。不同模型的 token 含义和单价都不同，加在一起没有意义，所以不画模型合计，也不把模型合并成"其他"。

## 行为

### 拆分维度

| 情况 | 拆分方式 |
|---|---|
| 管理员，未选用户 | 按用户（与现在相同） |
| 管理员已选用户，或非管理员 | 按模型 |

- Key、客户端、模型筛选只用于缩小数据范围，不再参与拆分维度的轮换。
- 已筛选到单个模型时，图上只有这个模型一条线。

### 用哪种"模型"

- 跟随模型分布表上已有的"实际模型 / 请求模型"切换，默认用实际模型。
- 这个切换的状态从 `UsageTab` 的局部状态上移，由趋势图和分布表共用，两处始终一致。按模型分线时，趋势图上方的说明行旁边也放一个同样的切换，绑定同一个状态，看图时不用滚到下面去切换。
- 请求模型为空的记录一律按其实际模型计，不再出现"Legacy"。这些记录都产生于 2026-09-06 之前：当时还没有 Key 模型映射，请求模型就是实际模型。线上 D1 查询显示，2026-10 起没有空值。这一规则在趋势图、模型分布表和请求模型筛选中统一生效，同时去掉筛选里的"Legacy"选项。不回填数据库：用量表主键含请求模型，回填会和过渡期已有的行冲突。

### 按模型分线时的显示

- 每个模型一条线，只画细线，线下不填充。
- 按当前时间范围内的总量从高到低排序，默认显示前 6 个模型。其余模型保留在图例中、初始为隐藏，点击图例可以显示，再点一次隐藏。
- 指标为 token 时，不画跨模型合计的 Cache 虚线。
- 悬停提示按该时段的用量从高到低列出各模型，每行包括：
  - 值：token 数，或请求数；
  - 指标为 token 且该模型有缓存时，标出其中的缓存 token 数；
  - 费用：沿用现有的 `costData`。
- 时段链接（点某天查看当天）的行为不变。

### 按用户分线时

保持现状：线下填充，指标为 token 时画 Cache 虚线，所有线默认显示。

### 说明文字

趋势图上方新增一行说明（`dash.chartLinesBy*`），说明当前按什么拆分：

- 按用户分线时，提示选择一个用户即可按模型拆分；
- 按模型分线时，说明是实际模型还是请求模型、按用量从高到低，并提示"点击图例可显示或隐藏模型"。

原有的筛选提示（`formatUsageFilterHint`）说明的是分布表的剩余维度，与趋势图无关，保持不变。

中英文文案都在 `i18n.ts` 中补齐。

## 实现结构

1. **纯函数（`state/usage-chart.ts`，新文件）**
   - `chartGrouping(isAdmin, filters)`：返回 `"user"` 或 `"model"`。
   - `buildUsageChart(rows, buckets, opts)`：返回每条线的 `data`、`cost`、`cache`，以及按总量排好的顺序和默认可见集合（前 6）。`opts` 包括拆分方式、模型种类、指标和时区。
   - `state/usage.ts` 里的 `chart` 改为调用这两个函数，删除内联的分组逻辑。
2. **`TimeSeriesChart`（向后兼容的可选参数）**
   - `ChartDataset.hidden?: boolean`：初始隐藏，图例可以切换。
   - 已有的 `fill` 继续沿用；按模型分线时传 `fill: false`。
   - `ChartDataset.cacheData?: number[]`：在提示框中显示缓存 token 数。
   - 记住用户在图例中显示或隐藏的线（按线名），自动刷新重建图表后保持不变。
   - 提示框按值从高到低排序。只在按模型拆分时由 `UsageTab` 开启，用参数 `sortTooltip` 控制，其他图表不受影响。
3. **请求模型回退**：在接口适配层 `api/usage.ts` 的 `adaptUsageRow` 中，把空的请求模型换成实际模型，所有下游（趋势图、分布表、筛选、维度列表）只会看到真实的模型名。删除 `LEGACY_INCOMING_MODEL_OPTION` 及其分支；万一实际模型也缺失，标为现有的"未知"文案。界面上沿用现有叫法：路由模型（实际模型）和传入模型（请求模型）。
4. **`UsageTab`**：上移"实际 / 请求模型"状态并传给 `useUsage`；根据拆分方式设置 `fill`、`hidden`，以及是否加 Cache 线。
5. **i18n**：新增拆分说明和图例提示的文案，包括中文和英文；不再使用的 Legacy 文案一并删除。
