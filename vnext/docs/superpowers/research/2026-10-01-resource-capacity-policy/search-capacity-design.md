# Hosted search capacity design

Date: 2026-10-01. Target checkout: `.worktrees/cfw-resource-rollback-fix`, supplied HEAD `648a521e`. Read-only source review except this report; no tests, benchmark, CI, network, or deployment. Previous execution and capacity audits are under `vnext/docs/superpowers/research/2026-10-01-{hosted-search-execution-contracts,diagnostic-resource-contracts}/`. Paths below are relative to `vnext/packages/gateway/` unless stated otherwise.

## Recommended implementation policy

Implement independent admission owners, sharing a single typed `HostedSearchCapacityError` whose reason is safe metadata, not user/provider text. The existing protocol owner terminates the response; capacity must never become an ordinary search-error snippet, fallback attempt, missing-private-payload notice, or successful completion. Do not change normal fanout, batching, result ordering, source annotations, or admitted replay semantics.

| Resource | Provisional default | Owner and admission point | Excess outcome |
| --- | --- | --- | --- |
| Logical operation work | 64 units per invocation | Search execution scope, before operation parser, argument slicing, slot construction or provider start | Reject whole offending original function call; no allocation/start for that call |
| Successful HTTP body | 1 MiB per HTTP response | Shared provider streaming reader, before full text/JSON parse | Stop body reading and throw typed capacity failure |
| Cumulative successful body ingress | 8 MiB per invocation, never refunded | One counter in execution scope; capability passed through provider request and every fallback/page fetch | Reject chunk before retaining it; terminate invocation without another engine/model attempt |
| Responses private replay | 64 entries and 4 MiB estimated retained charge | Owned private writer, before insertion and completed-item frames | Reject write atomically; preserve earlier entries until normal disposal |
| Active page cache | 64 entries and 2 MiB estimated retained charge | Search execution scope's cache abstraction, before insertion | Throw typed capacity failure; do not evict/refetch or publish a successful page result |
| Chat generated continuation state | 4 MiB estimated retained charge | Chat loop, before appending new assistant/tool messages and new annotations | Throw through existing Chat result owner; no next `run()` |

These are actionable implementation defaults, **not measured safe workerd release limits**. Keep them in one typed policy module with constructor injection for deterministic boundary tests; no environment variables, dashboard settings, migrations, or production release claims are needed in this slice. Reject invalid policy values at construction. Keep budget roles distinct even when defaults align.

Rationale from current behavior: `operations.ts:28-32` maps low/medium/high to 10/20/40 results; `:47-51` caps snippets at 2,048 characters; page content has a 10,240-byte output cap (`types.ts`). `providers/shared.ts` caps query length at 1,000 characters. Responses retains its separate 30-turn policy. Sixty-four operations permit two queries in each of 30 turns plus four other operations, without treating 30 turns as a work limit. Existing `plan-operations.test.ts:57-105` and `execution-scope.test.ts:48,124,139-143` cover two-query and mixed search/open/find fanout and same-page reuse; the defaults preserve these documented shapes, not an inferred production distribution.

Forty snippets at up to 2,048 UTF-16 code units have about 160 KiB of string charge; a 1 MiB raw body permits materially larger provider content/metadata before the existing snippet projection. JSON escapes, long titles/URLs, and unselected provider results can still exceed it and should fail explicitly. Eight MiB cumulative ingress allows multiple substantial provider responses while preventing the naive 64 operations × 1 MiB = 64 MiB retained input allowance. Four MiB replay admits roughly 25 such maximum-snippet query result sets before arguments/metadata overhead, or more ordinary short-result turns; high-context searches can intentionally hit bytes before operations. Two MiB page cache allows 64 ordinary 10 KiB pages plus UTF-16/URL/title/container charges. None of these arithmetic examples establishes heap usage or latency.

## Operation preflight and reentry

`tools/web-search/execution-scope.ts:101` currently calls `splitWebSearchCalls` directly. `plan-operations.ts` expands using `parseWebSearchOperations` and retains slices of raw arguments. Add a scope-owned atomic admission before this work. Count supported non-undefined arrays by length, supported non-array values as one, unsupported arrays by length, and unsupported non-arrays as one. Charge `max(1, sum)` for null, empty or all-empty-array calls. Supported properties explicitly set to undefined are skipped, matching the parser; unsupported undefined still counts. Sparse array holes count. Do not inspect each array element to compute its length. Use own-property enumeration and saturating arithmetic/early exit, without allocating `Object.entries()` for a large input.

An admitted token belongs to exactly one scope and one original argument object, and is consumed once by either preparation or the existing iteration-refusal path. A practical narrow API is `admit(args)` followed by `prepare(admission)`, with scope identity and one-use checks. A discarded admission is not refunded. Parser helpers can remain usable for low-level tests/non-hosted routes, but hosted callers must have no bypass path. No rollback of previously admitted calls is promised.

Move admission before both early refusal branches: Responses `responses/interceptors/server-tools/web-search.ts:475` and Chat `chat-completions/interceptors/with-chat-completions-web-search-shim.ts:344`. Each already creates one execution scope outside reentry; retain counters there. Count queries, including queries merged into one slot, rather than slots, upstream `max_tool_calls`, or provider HTTP attempts. The cap does not bound the already-decoded upstream arguments object, JSON repair, arbitrary raw upstream traffic, or caller-held input. Preserve the original argument slices, including ignored fields.

## Successful-body ingress

Replace successful `.json()`/`.text()` reads in Tavily search/extract, Jina search/reader, LangSearch search, Microsoft grounding search/reader, Bing HTML and Copilot search. Relevant current reads: provider files Tavily `:127,188`, Jina `:165,230`, LangSearch `:77`, Microsoft `:118,170`, Bing `:132`, Copilot `:183`. Copilot search transport can return a whole text/SSE representation: bound the raw successful response before its existing parser. This policy does not apply to generic model-output streaming or alpha passthrough.

Add an optional invocation ingress capability to search/fetch request types and forward it explicitly to per-URL helpers, fallback engines and retry paths. Every built-in successful reader enforces the per-response cap even outside hosted use; hosted callers also provide the cumulative capability. Provider instances are shared/configured objects and must not themselves own request counters. A provider response consumes cumulative bytes once; normalization, replay reads, cached pages, and parsing do not recharge them. Failed HTTP diagnostic bodies retain their separate existing policy. Usage `finally` remains valid for provider attempts that actually started.

Use a streaming reader with bounded fixed-size storage blocks; do not retain a JS array element per tiny network chunk or retain a small `subarray` view into an arbitrarily large backing buffer. For each delivered chunk, check per-body remaining and atomically debit shared cumulative remaining synchronously before copying. If the full chunk cannot fit, cancel reading and throw; do not keep its prefix or parse partial JSON. Exactly-at-limit requires the following EOF read; limit plus one is rejected. Ignore `Content-Length` as an authority. An absent native body is empty input, not permission to call an unbounded `.text()` fallback; update synthetic responses in tests accordingly. Complete decoding and JSON parsing occur only after EOF admission. Always release the reader; observe cancellation without making a noncooperative cancel promise the capacity decision's completion gate.

Cumulative accounting is monotonic: successful reading that later fails JSON validation still consumed ingress, and fallback/retry does not replenish it. Concurrent provider readers share one counter with no await between check and debit. No queue or serialization is introduced. A runtime/network chunk can already have allocated before application admission; decompression, external provider implementations, parser expansion, HTTP machinery and decoded/parsed copies remain outside the charged-byte quantity. Eight MiB is therefore a cumulative retained-input gate, not an isolate heap ceiling.

Critical propagation: provider broad catches currently turn errors into `unavailable`; Jina additionally has `.json().catch(() => null)`; reader helpers turn errors into per-URL failures; `operations.ts:530` and `:650` turn exceptions into snippets. Each boundary and configured-engine fallback must rethrow the typed capacity exception before its ordinary-error handling. Test that no later fallback engine starts after overflow. Scope cancellation and protocol terminal handling remain the existing owners, not the reader.

## Retained replay and page cache

The default private scope (`orchestrator/server-tools/private-payload-store.ts:85`) currently borrows typed graphs with no accounting. `private-payload.ts` permits arbitrary function-call extensions, so counting only `arguments` and visible IR strings is insufficient. Use a bounded full-graph estimator on write, not JSON serialization, cloning, or repeated scans on read. Suggested deterministic charge: strings `32 + 2 * length`, property-name strings by the same formula, objects 64, arrays 64 plus 8 per slot, properties 16, primitives 8. Charge item ID too. This is a conservative application estimate with explicit constants, not measured engine allocation.

Inspect all own data properties, including non-enumerable and symbol-keyed fields, or reject unsupported descriptors/types rather than silently exclude them. Reject getters, exotic prototypes, functions and cycles in owned payloads; gateway-produced JSON-like payloads do not require those extensions. Preserve valid unknown JSON fields. Bound estimator work to 65,536 visited values and depth 64 per write; crossing either rejects as retention capacity. Count duplicate references conservatively (cycle detection on active ancestors), so sharing does not weaken admission. Use own-key reflection plus per-property descriptor reads rather than a full descriptor map. Own-key reflection itself can allocate an array proportional to an already-created object; the visited-value ceiling bounds subsequent traversal, not that earlier reflection allocation. This is a retention gate and must not be presented as pre-allocation admission for arbitrary injected graphs. Reject symbol keys and exotics upon encounter. Document that trusted producers must not mutate retained graphs after admission; static readonly typing alone does not provide that guarantee.

Store each entry's charge. On replacement, compute candidate against `total - oldCharge`; only replace after successful admission. Never evict a live private entry, fall back to `undefined`, freeze caller objects, or silently remove original extension fields. Reset entries and charges on dispose. The existing `writer.registerPrivatePayload` can retain its synchronous signature and throw the typed exception; no generic result union is required for a minimal change. Its caller in `responses/interceptors/server-tool-shim.ts:952` already writes before completed frames.

Use the same estimator for page-cache key and entry, through a small owned cache abstraction replacing direct `Map.set` in `operations.ts:645`. Check before insertion and before `perUrl` publishes that page as successful; preserve existing lookup/dedup. Count the actual content/title/url graph, not untrusted `fullContentBytes`, which describes source size rather than retained content. No TTL or LRU eviction: refetch could alter content, billing and find results. A partially admitted multi-page batch may leave earlier entries internally until disposal, but the failing batch must not report a partial success as normal. Late results cannot write after scope closure. Direct provider output and pending batch maps remain separate temporary owners.

Externally injected legacy private stores remain delegated/trusted and are not certified by the owned retention policy; do not clear them or shadow historical foreign entries. Mention this coverage limitation explicitly in release notes. Likewise, injected providers that return constructed objects without using the body reader are outside raw HTTP ingress enforcement, although cache and owned replay checks still run.

## Chat retention and precise terminal behavior

An owned private-store cap covers Responses only. Chat retains rendered tool strings, generated assistant messages containing original call arguments, and accumulating URL annotations (`with-chat-completions-web-search-shim.ts:341-385`). It therefore needs its own generated-state estimate if claiming both protocols' hosted retention is bounded. Charge each newly added assistant/tool message once plus new annotation entries before appending them; charge original tool-call argument strings and extension fields too. Do not rescan or recharge base input and all historical messages on every turn. Do not charge cache/replay as though the same byte budget owned all containers. An existing input history is outside this increment. The 4 MiB generated-state budget is distinct from Responses private retention, and does not bound the output pipeline or caller-retained data.

Responses capacity failures propagate into `runMultiTurnLoop`'s existing catch (`server-tool-shim.ts:1084`), yielding its normal `server_error`/failed lifecycle and settling final metadata. No next model call or completed overflowing item is emitted. Chat throws from its loop through `ChatWebSearchResultOwner.wrap`; retain the existing pipeline error owner and cleanup, without inventing a stop chunk that claims success. The implementation must verify native JSON/error rendering at the established outer owner, not add a second response writer. Safe exception text can name capacity category and limit only.

## Discriminating implementation tests

1. Tiny injected budget: exact boundary passes; one extra unit fails before parser/slice/slot/provider spies; two clean queries charge two despite one plan. Include null, empty arrays, supported undefined, unsupported scalar/array, holes, malformed values and many original calls.
2. Both protocols retain the same counter across reentry and count iteration-refusal calls; failure prevents next `run()`; previous admitted work and usage are not declared unexecuted. Normal mixed fanout and same-page reuse remain intact.
3. Success reader: exact EOF, plus-one, absent/false Content-Length, split multibyte JSON, single oversized chunk, many tiny chunks, invalid JSON, and no-body response. Never invoke full-response `.json()`/`.text()`. Confirm all built-in successful paths use the helper, including Bing/Copilot and reader-page paths.
4. Two concurrent responses each below 1 MiB but jointly beyond a tiny injected cumulative cap: only allowed bytes are retained, exception survives provider/helper/operations catches, no fallback/retry/model continuation starts, and started usage attempts remain recorded.
5. Private writer: replacement net charge, rejected write leaves old value, long ignored arguments/unknown fields, nested extensions, cycles/exotics/accessors, exact count/byte limits, disposal reset; no successful item or missing-payload notice after rejected write.
6. Cache: exact count/byte boundary, title/URL accounted, same URL replacement, preserved cache hit/find content, no LRU refetch, and no write after closure. Inject oversized normalized page to distinguish cache retention from HTTP cap.
7. Chat: generated arguments/tool output/annotation bytes consume its own budget; initial history is not repeatedly charged; byte exhaustion prevents append and next model call. Responses private-store tests alone do not qualify this.
8. Preserve ordinary malformed-tool/provider-error behavior below limits and explicit external-store delegation. Follow existing protocol cleanup verification without redoing the previous cancellation audit.

Local workerd qualification remains required before choosing release defaults: representative high-context multi-query and open/find cases, concurrent invocations, UTF-16/JSON amplification, and cumulative-body rejection. This design establishes admission semantics and provisional constants only; it makes no CPU, latency, global-memory, or production-safety claim.
