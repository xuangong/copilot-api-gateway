# vNext architecture review from subsystem ownership

Date: 2026-09-30. Reviewed source: local `vNext` at `52e7ad67e88e15122bff50087588f37b3e3216e4` plus its preserved collaboration overlay. This is a source/call-chain review. No product code, tests, builds, resource measurements, production bindings or deployments were changed or executed for this review.

The resulting [subsystem design](../../specs/2026-09-30-vnext-subsystem-architecture-design.md) defines responsibilities, ports, state ownership, resource budgets, completion milestones and compatibility requirements. Proposed interfaces and priorities are explicitly future work. The prior [request-boundary implementation](../2026-09-30-cfw-resource-remediation/request-boundaries-results.md) remains implemented; its unfinished performance comparison remains unfinished.

## Decision

Retain the modular monolith and existing host/provider/protocol boundaries. The recent lazy source adapter, routing projection/materialization split and request-owned scheduler are sound improvements. The next useful work is to clarify authority, lifetime and completion contracts inside that structure.

This review found one concrete local invalidation omission, a transport-dependent access-policy difference, and several remaining ownership/atomicity/resource-bound gaps. Source reasoning supports the stated consequences; it does not establish a new production incident, measured regression, memory leak or whole-service performance gain.

## Findings, ordered by action priority

### R1 — P1: Logout omits local session-cache invalidation

`/auth/logout` calls `getRepo().sessions.deleteByToken` at [auth/routes.ts:154](../../../../packages/gateway/src/control-plane/auth/routes.ts#L154). The SQL implementation deletes the row at [repo/shared/repos.ts:1007](../../../../packages/gateway/src/repo/shared/repos.ts#L1007), but [observeConfigurationWrites:292](../../../../packages/gateway/src/repo/configuration-cache.ts#L292) wraps only session `create`, `deleteByUserId` and `deleteExpired`.

HTTP inference pins configuration before authentication ([app.ts:71](../../../../packages/gateway/src/app.ts#L71)). Its credential resolver uses that view, whose [session cache:116](../../../../packages/gateway/src/repo/configuration-cache.ts#L116) accepts an unexpired entry at the same snapshot revision. Therefore a previously cached token can remain usable for later local inference admissions after logout until a refresh observes the changed revision. The [SQL delete trigger](../../../../packages/gateway/migrations/0010_configuration_revision.sql#L62) supplies eventual revision invalidation; this is not permanent non-revocation. WS fresh reads follow a different path.

The missing notification is confirmed in source. The duration and runtime reproduction were not measured here. Do not promise an exact 30-second window: refresh timing/failure and the existing authorization lease affect observation. Already-admitted requests need an explicit policy distinct from later admissions.

**Design response:** S2 owns `SessionLifecycle.revoke`, including durable mutation and local invalidation; S3 owns cross-instance revision freshness. First fix this exact omission, then replace the fragile method-name inventory with an exhaustive command/decorator boundary. Verify the public logout-to-next-inference path with a real local repository in its implementation task.

### R2 — P1: Catalog retention can exceed the routing projection's byte budget

[CatalogCoordinator:71](../../../../packages/gateway/src/data-plane/providers/catalog-coordinator.ts#L71) retains a result containing a snapshot, full upstream row and proxies. [Installation:120](../../../../packages/gateway/src/data-plane/providers/catalog-coordinator.ts#L120) evicts by 512 entries only. [RoutingProjectionCache:74](../../../../packages/gateway/src/data-plane/providers/routing-projection.ts#L74) separately limits 512 upstreams, 16,384 models and 16 MiB estimated data.

A catalog too large for the projection cache can still be held by the coordinator. Shared model references can reduce duplication, but the projection cap does not cap total catalog retention. Configuration snapshots also retain complete rows. This is a confirmed budget/ownership gap, not a demonstrated cause of the earlier OOM or a claim that every catalog is duplicated.

**Design response:** S4 owns aggregate retained bytes/models and separates a catalog publication from request authority/credentials. Preserve accepted-catalog behavior by making oversized results request-local where possible. Charge retained graphs once, keep eviction independent of durable publication, and preserve stale/cache-only/explicit semantics. S5 keeps its own bounded derived index.

### R3 — P1 policy decision: Disabled API-key owners differ between HTTP and WS

[resolveCredential:63](../../../../packages/gateway/src/shared/credential-auth.ts#L63) resolves an API key without checking its owner unless `requireEnabledOwner` is supplied. [HTTP middleware:69](../../../../packages/gateway/src/control-plane/auth/session-auth.ts#L69) uses the default; [WS authorization and each turn](../../../../packages/gateway/src/data-plane/chat-flow/responses/session.ts#L46) explicitly request the owner check.

The difference is confirmed for API-key resolution, not for all credential kinds: session and legacy user-key paths already inspect `user.disabled`. This may preserve earlier HTTP behavior; the review does not silently classify that compatibility policy as a newly introduced exploit.

**Design response:** S2 exposes a named inference policy. Decide whether HTTP must converge with WS or retain an explicit legacy exception, then implement and cover it as a behavior change. Do not hide the choice inside an interface extraction.

### R4 — P2: Pinned configuration still exposes broad mutation/current-state capability

[getDataPlaneRepo:51](../../../../packages/gateway/src/repo/index.ts#L51) and `pinnedView` return a complete writable `Repo`. [createView:230](../../../../packages/gateway/src/repo/configuration-cache.ts#L230) overrides selected reads and forwards other methods to raw authority. Credential recovery deliberately uses current state through another accessor. These mechanisms have useful semantics, but callers cannot distinguish them through narrow types.

**Design response:** S3 publishes read-only auth/routing views; S2/S8 use explicit authoritative mutation/current-credential ports. Keep the existing warm behavior and CAS fences. Avoid both a universal service context and an extra SQL read on every inference request merely for structural purity. The logout omission is the concrete reason to make mutation/invalidation exhaustive.

### R5 — P2: Producer shape is recovered from telemetry; completion has several representations

[traverseTranslation:185](../../../../packages/gateway/src/data-plane/chat-flow/shared/traverse-translation.ts#L185) casts hub frames into a source-typed result. [Responses source preparation:30](../../../../packages/gateway/src/data-plane/chat-flow/responses/source-result.ts#L30) then selects the real domain using `modelIdentity.translatorPair.hub`. The new adapter localizes this boundary but does not make the producer contract explicit globally.

[ResponsesTurnCompletion:195](../../../../packages/gateway/src/data-plane/chat-flow/responses/turn.ts#L195) reports outcome/cleanup. Other protocols use [KitCanonicalCompletion attached to Response](../../../../packages/chat-flow-kit/src/serve-template.ts#L29). Telemetry and persistence orchestration still live in multiple renderers. [recordPerformance:275](../../../../packages/gateway/src/data-plane/chat-flow/shared/respond-telemetry.ts#L275) projects both legacy and current metrics.

Required [snapshot persistence precedes `response.completed`](../../../../packages/gateway/src/data-plane/chat-flow/responses/turn.ts#L407). HTTP [JSON delivery](../../../../packages/gateway/src/data-plane/chat-flow/responses/respond.ts#L24) and [SSE terminal cleanup](../../../../packages/gateway/src/data-plane/chat-flow/shared/demand-sse.ts#L40) already separate delivery from later settlement. However, the turn [finalizer](../../../../packages/gateway/src/data-plane/chat-flow/responses/turn.ts#L307) awaits source closure, pending snapshot work, usage/performance and dump finalization. [WS publication and next-turn admission](../../../../packages/gateway/src/data-plane/chat-flow/responses/session.ts#L174) depend on that broader cleanup result, including [private continuation publication](../../../../packages/gateway/src/data-plane/chat-flow/responses/session.ts#L248). Ordinary dump storage failures are [logged and absorbed](../../../../packages/gateway/src/shared/dump/accumulator.ts#L110); dump latency still belongs to this waiting chain, while usage/performance errors can mark cleanup incomplete. This is a source-established dependency, not a measured delay or reproduced WS failure.

**Design response:** S7 normalizes an explicitly tagged producer domain. S6 owns execution/cleanup facts; S1 owns delivery observations; S9 owns required continuation readiness; S10 projects stable facts into compatible sinks. Distinguish execution release, continuation readiness, accounting acceptance and diagnostic settlement, without letting a projection receipt retroactively change the semantic outcome. Avoid a completion promise that waits on the same sinks that await it. Merely exposing separate receipts must retain current HTTP delivery and WS completion prerequisites; changing which receipt gates another WS turn requires a separate compatibility decision. R8 addresses the accounting acceptance guarantee needed before moving its work.

The known JSON policy-refusal mapping remains legitimate recorded evidence: [HTTP renderer](../../../../packages/gateway/src/data-plane/chat-flow/responses/respond.ts#L20) can return wire 200 while [turn/dump settlement](../../../../packages/gateway/src/data-plane/chat-flow/responses/turn.ts#L307) records semantic failure/dump 502. A scalar status equality rule would erase this distinction; changing public behavior needs its own decision.

### R6 — P2: Resource limits describe different buffers, not one request budget

[demandSse:5](../../../../packages/gateway/src/data-plane/chat-flow/shared/demand-sse.ts#L5) bounds the encoded queue/chunks to 16 KiB but retains one complete serialized frame. [Responses native JSON ingestion:167](../../../../packages/gateway/src/data-plane/chat-flow/responses/attempt.ts#L167) materializes a complete body. Turn output, optional history, affinity preparation and bounded upstream capture can overlap with those representations. [WS limits](../../../../packages/gateway/src/data-plane/chat-flow/responses/session-limits.ts#L1) separately constrain inbound/frame/output/local-state/cleanup.

The durable [snapshot store](../../../../packages/responses-store/src/sql.ts#L43) reads/parses complete `items_json` and [serializes the full continuation on save](../../../../packages/responses-store/src/sql.ts#L100), with no per-snapshot byte contract in that adapter. The [private WS state cap](../../../../packages/gateway/src/data-plane/chat-flow/responses/local-continuation.ts#L20) is checked after serialization; it bounds retained state, not transient allocation. Both stores share the [canonical compaction-window rule](../../../../packages/gateway/src/data-plane/dispatch/responses-store-bridge.ts#L71), which cannot be replaced by silent history truncation.

The shared [request-body reader](../../../../packages/gateway/src/shared/dump/request-body.ts#L30) uses `arrayBuffer()` without an incremental cap in that function. This is a reader-local observation, not a claim that every route or platform lacks input limits.

Capture has distinct budgets too. [Upstream prefixes](../../../../packages/gateway/src/shared/dump/upstream-attempts.ts#L7) have explicit attempt/body/metadata limits, while the canonical [dump event log](../../../../packages/gateway/src/shared/dump/accumulator.ts#L233) appends frames without a cumulative byte cap in that accumulator. [Compression and preparation](../../../../packages/gateway/src/repo/dump-store.ts#L180) are sequential with explicit reference release, but materialize whole compressed bodies. Canonical HTTP capture [forwards one reader](../../../../packages/gateway/src/shared/dump/accumulator.ts#L350); the [legacy/non-canonical fallback](../../../../packages/gateway/src/shared/dump/accumulator.ts#L330) still tees and fully drains a capture branch. Neither “all capture is bounded” nor “every response is teed” describes the current implementation.

**Design response:** S1/S6/S8/S9/S10 each name their buffers, aggregate limit and release milestone. Preserve existing bounded upstream capture, demand and ownership-transfer work. Define continuation size/expiry/read-after-write outcomes and capture complete/truncated/omitted/failed outcomes explicitly; a bounded spool is a possible target when exact capture is required, not an existing capability. The source alone does not prove leak, peak memory or a net CPU reduction; adding request rejection or changing dump completeness is a product change, not an implicit optimization. R9 covers payload readback and subscriber limits.

### R7 — P2: One-time challenge contracts and management prewarm need explicit owners

The CFW OAuth/email/magic store [reads then deletes](../../../../packages/gateway/src/control-plane/auth/stores.ts#L51), so its interface does not provide atomic consumption. Local OAuth state cleanup happens during save, while [read:62](../../../../packages/gateway/src/control-plane/auth/stores.ts#L62) does not inspect age. The normal callback accepts that returned state. Agent Remote's browser-bound OAuth uses a separate conditional repository lifecycle; it must not be conflated with the normal path.

Separately, [session middleware:72](../../../../packages/gateway/src/control-plane/auth/session-auth.ts#L72) has a growing exclusion list for Copilot prewarming on management requests. Authentication and provider token acquisition remain coupled outside the inference snapshot path.

**Design response:** S2 owns expiry-aware atomic challenge consumption. S11 operations explicitly acquire an S8 credential when required; generic authentication only establishes identity/policy. These are source-level lifecycle gaps, not evidence of an observed replay or measured control-plane latency.

### R8 — P2: Accounting has request-local guards; quota reads analytical history

[Responses settlement](../../../../packages/gateway/src/data-plane/chat-flow/responses/turn.ts#L129) sets its `persisted` guard before awaiting usage and performance. [recordUsage](../../../../packages/gateway/src/data-plane/chat-flow/shared/respond-telemetry.ts#L221) skips zero/absent usage and concurrently writes usage and API-key last-use. The [ordinary usage repository](../../../../packages/gateway/src/repo/shared/repos.ts#L808) increments one row per billing dimension, then `usage_requests`. [Legacy performance](../../../../packages/gateway/src/repo/shared/repos.ts#L1251) writes summary and histogram sequentially; [current metrics](../../../../packages/gateway/src/repo/performance-metrics.ts#L16) use one SQL statement but are separately invoked by [recordPerformance](../../../../packages/gateway/src/data-plane/chat-flow/shared/respond-telemetry.ts#L289). Image [subcall accounting](../../../../packages/gateway/src/data-plane/shared/token-usage.ts#L129) has its own `requests: 1` policy. These aggregates do not represent every accepted HTTP request.

The ordinary shared [SqlExecutor](../../../../packages/gateway/src/repo/shared/executor.ts#L5) exposes statement-level `all/first/run`. [Bun](../../../../apps/platform-bun/src/bun-sqlite-repo.ts#L16) and [D1](../../../../apps/platform-cloudflare/src/d1-repo.ts#L165) execute those calls separately; these accounting sequences have no encompassing transaction or durable fact ID in the reviewed path. **D1 supports atomic `batch`, and migration helpers use it** for [usage conversion](../../../../apps/platform-cloudflare/src/d1-repo.ts#L93) and [identity-index replacement](../../../../apps/platform-cloudflare/src/d1-repo.ts#L129). This finding does not mean all repository writes or all D1 operations lack atomicity. Partial multi-statement failure and duplicate increments on naive retry are inferred risks of these sequences; neither was reproduced here. Request-local guards are not durable idempotency.

Quota's precise call chain is [template admission](../../../../packages/chat-flow-kit/src/serve-template.ts#L244) → [runQuotaGate](../../../../packages/gateway/src/data-plane/chat-flow/shared/quota-gate.ts#L37) → [checkQuota](../../../../packages/gateway/src/data-plane/observability/quota.ts#L38) → [usage.query](../../../../packages/gateway/src/repo/shared/repos.ts#L851). When configured, it retrieves both current-month dimension/request result sets and sums requests, weighted tokens and cost in JavaScript; unconfigured keys bypass the usage read. Exceptions explicitly fail open. This is already a soft quota over settled totals, not a strict reservation gate. Concurrent admissions can inspect the same totals, but no overshoot magnitude is measured. Responses [history expansion/affinity preprocessing](../../../../packages/gateway/src/data-plane/chat-flow/responses/serve.ts#L150) also occurs before this gate.

**Design response:** S6 emits an immutable accounting fact with request/attempt/subcall identity and stable model/pricing/token dimensions; S10/S12 explicitly choose its acceptance and projection guarantees. A durable retry option requires an idempotent fact key, explicit transactional acceptance and retryable projections; blindly replaying existing incremental writes is insufficient. Do not introduce a durable queue solely to unify projection inputs. Preserve current zero-usage, subcall and pricing semantics. Expose a scoped monthly aggregate quota read to avoid full detail reconstruction while retaining the current fail-open policy. Strict reservation/commit/release, altered error precedence or earlier admission are separate behavior decisions. Keep API-key last-use metadata separate from accounting durability.

### R9 — P2: Query aggregation is partly adopted; cardinality and freshness contracts differ

The [usage overview](../../../../packages/gateway/src/repo/usage-overview.ts#L48) is implemented, validates bucket/page bounds, and executes SQL aggregation. The [Keys monthly total](../../../../apps/dashboard/src/api/keys.ts#L170) already uses it. The main [Usage reload](../../../../apps/dashboard/src/state/usage.ts#L303) still fetches detail plus participants; its [28-day strip](../../../../apps/dashboard/src/state/usage.ts#L340) fetches 117 days of detail. The [detail route](../../../../packages/gateway/src/control-plane/token-usage/routes.ts#L152) does not use overview's range/page limits and [reconstructs the full result](../../../../packages/gateway/src/repo/shared/repos.ts#L851). Overview bounds output, but its [three separate queries](../../../../packages/gateway/src/repo/usage-overview.ts#L100) each process matching history; the offset cursor is explicitly not a snapshot. Neither bounded database work nor atomic consistency across those reads is established.

The current [performance route](../../../../packages/gateway/src/control-plane/performance/routes.ts#L231) limits the range to 366 days. Its [SQL query](../../../../packages/gateway/src/repo/performance-metrics.ts#L36) aggregates distributions but has no group/page bound, and [browser state](../../../../apps/dashboard/src/state/performance.ts#L20) filters and combines the returned groups. Range semantics also differ: [usage](../../../../packages/gateway/src/repo/shared/repos.ts#L795) is end-exclusive, while [performance metrics](../../../../packages/gateway/src/repo/performance-metrics.ts#L39) include `end`.

Dump [lists are metadata-only and capped](../../../../packages/gateway/src/control-plane/dump/routes.ts#L65), but [detail/export readback](../../../../packages/gateway/src/repo/dump-store.ts#L450) loads/decompresses complete bodies and parses event arrays. The per-isolate [broker queue](../../../../packages/gateway/src/shared/runtime/event-target-channel-broker.ts#L46) has no subscriber queue cap, and [dashboard merging](../../../../apps/dashboard/src/state/dumps.ts#L9) retains paginated/live metadata without a retained-list cap. These are separate resource contracts from capture prefixes. Main Usage reload has no request-generation guard; performance suppresses stale UI updates without aborting its request; dumps have [separate abort controllers](../../../../apps/dashboard/src/state/dumps.ts#L32). No race or resource incident was reproduced.

**Design response:** S11 consumes scoped overview/detail-page/performance-summary/dump-preview ports from S10/S12. Complete the existing overview adoption where UTC aggregation preserves current local-day semantics; do not call the endpoint unimplemented or silently change timezone/counting behavior. Specify grouping, output/work bounds, cursor semantics, unknown/unpriced data and freshness. Separate bounded preview from full export; treat live metadata as a hint with bounded queues and authoritative gap reconciliation. Propagate cancellation and generation ownership through read hooks. Preserve [API-key/shared-view scoping](../../../../packages/gateway/src/control-plane/token-usage/routes.ts#L131) and [dump owner/admin access](../../../../packages/gateway/src/control-plane/dump/routes.ts#L29); presentation caches must never become authorization or quota authority.

### R10 — P2: Logical subsystem boundaries share SQL capacity and maintenance work

[Cloudflare composition](../../../../apps/platform-cloudflare/src/bootstrap.ts#L52) sends the same `env.DB` to the main repository, global SQL adapter and Responses snapshot store. [Dump composition](../../../../packages/gateway/src/bootstrap.ts#L29) uses that SQL adapter plus R2 files. [Shared repository construction](../../../../packages/gateway/src/repo/shared/repos.ts#L1305) puts configuration/auth, usage/performance and other repository domains behind one executor. [Bun](../../../../apps/platform-bun/src/bootstrap.ts#L35) likewise uses one SQLite database plus a separate dump-file root. Dump bodies are already physically separated; snapshots and diagnostic/accounting metadata still share SQL capacity with authority. This is confirmed wiring, not evidence of current capacity pressure or an outage.

[Scheduled maintenance](../../../../apps/platform-cloudflare/src/worker.ts#L10) calls [serial domain sweepers](../../../../packages/gateway/src/maintenance.ts#L11), catching each domain failure independently. [Responses expiry](../../../../packages/gateway/src/responses-maintenance.ts#L3) is bounded to four batches of 100 deletions. [Dump maintenance](../../../../packages/gateway/src/repo/dump-maintenance.ts#L5) visits bounded keys/records and examines at most 100 file candidates before token-fenced claim/reference checks. Snapshot and dump reads enforce logical expiry independently of reclamation. These existing candidate/row limits do not prove byte/work/time bounds or backlog convergence; a slow serial task can delay later domains without throwing.

The request-scoped [BackgroundExecutor](../../../../packages/platform/src/background.ts#L4) accepts promises, while [CFW ingress](../../../../apps/platform-cloudflare/src/responses-websocket.ts#L33) attaches them to the originating context and [Bun](../../../../apps/platform-bun/src/bootstrap.ts#L42) observes them in-process. This interface supplies ownership, not durable queuing, retries, concurrency admission or independent resource capacity.

**Design response:** S12 exposes domain-specific authority, continuation, accounting and diagnostic ports with explicit physical binding/capacity roles. First narrow capabilities and specify per-domain budgets; separate stores only with scoped read-after-write, commit ordering, idempotency and orphan-collection contracts. Preserve existing [staged dump publication](../../../../packages/gateway/src/repo/dump-store.ts#L269) and [collector fences](../../../../packages/gateway/src/repo/dump-maintenance.ts#L52). Give maintenance domain cursors, bounded work, last-success/progress and backlog semantics; keep read-time expiry authoritative. No platform memory/CPU/throughput improvement follows from these proposals without a separately authorized measurement phase.

## Established boundaries to retain

- HTTP and WS share the Responses turn. Source-result conversion is lazy and mode-specific; the turn owns producer cleanup, terminal validation and required history-before-success.
- Routing projection metadata is immutable and bounded. Materialized providers/fetchers/credential suppliers remain request-local and outside that projection; request-token Copilot is excluded from shared publication. Provider-owned reusable token caches are separate state, and R2 covers the coordinator's retained upstream rows. Owned affinity retains complete eligible ranking.
- Catalog publication uses identity, leases, generation and CAS checks; cached discovery is not authorization or opaque-state authority.
- Catalog refresh and dump publication retain the originating background executor. Remaining ambient helpers should be migrated selectively, without assuming every current use is wrong.
- Canonical HTTP capture forwards a single reader, and upstream diagnostic prefixes have attempt/body/metadata bounds. Legacy/non-canonical capture still tees and fully drains its branch; the canonical event log and full readback have separate capacity gaps. Retain staged file/SQL publication ownership and explicit reference release. Background scheduling does not remove resource cost.
- Durable continuation remains key-scoped, expiry-checked and committed before terminal success when retention applies. Private WS continuation remains latest-only and gated by native terminal acceptance plus current cleanup completion. Affinity's authoritative owner/incarnation/generation fence is distinct from cached discovery.
- Usage overview already serves monthly key totals; dump bodies already use R2/filesystem storage; maintenance already bounds selected candidates/rows and preserves logical expiry. Extend these boundaries rather than describing them as missing implementations.
- Host apps compose platform adapters; gateway composes domain workflows. Core must remain independent of LLM business code; management may call catalog/provider ports, while data-plane code cannot import management handlers.

## Review scope and disposition

The review examined runtime composition; identity/config/catalog/routing; request/provider/protocol/turn execution; and state/diagnostic/query/maintenance collaboration. It is not an exhaustive security audit or proof that all paths satisfy the proposed contracts. Three parallel source reviews were combined with root call-chain verification.
