## Findings

1. **Important — degrading optional Chat reasoning can delete a nonempty assistant message.** `vnext/packages/gateway/src/shared/affinity/analysis.ts:238-243` strips reasoning fields, then treats only `content` and `tool_calls` as evidence that the assistant message still has content. The Chat message schema is loose (`vnext/packages/protocols-llm/src/chat/index.ts:15-21`), and `refusal` is an existing Chat output field. A valid assistant message with `content: null`, `refusal: "I cannot help"`, and a gateway-owned `reasoning_opaque` is classified as degradable; `materialize(undefined)` removes the entire assistant message, including the visible refusal. This violates the optional whole-reasoning projection and changes next-turn history. A direct Bun probe using `stampAffinityItem` and `analyzeAffinityRequest` returned `{"classification":"degraded","materialized":{"messages":[{"role":"user","content":"next"}]}}` for that case. Preserve non-reasoning assistant fields when projecting, or reject a projection that cannot preserve them. Cover at least refusal and other accepted assistant payload fields.

2. **Important — a valid Responses `program_output` is silently dropped for Chat/Gemini clients.** `vnext/packages/translate/src/shared/client-opaque-state.ts:11-14` rejects `program_output` only when it contains `encrypted_content` or `fingerprint`. The protocol's `ResponsesProgramOutputItem` has `id`, `call_id`, `result`, and `status`, with neither opaque property (`vnext/packages/protocols-llm/src/responses/events.ts:194-200`). This native program state cannot be represented by either client protocol, yet `translateResponsesToChatBody` ignores it and `translateResponsesToGeminiEvents` emits a successful empty candidate. A direct Bun probe with `{type:"program_output",id:"po_1",call_id:"call_1",result:"42",status:"completed"}` returned Chat `{content:"",finish_reason:"stop"}` and Gemini `{parts:[],finishReason:"STOP"}`. Reject this item by its protocol type in these source adapters, including terminal-only output; keep the check confined to recognized Responses item slots so ordinary tool business properties remain untouched.
