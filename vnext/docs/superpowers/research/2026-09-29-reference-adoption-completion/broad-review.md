## Strengths

1. **Continuation has a real ownership boundary.** `responses/turn.ts`, `completion-snapshot.ts` and `session.ts` separate preparation, canonical event consumption, terminal publication, durable snapshot completion and cleanup. Failed/cancelled state is not promoted to reusable successful continuation. Native Bun/Workers adapters use the same session contract and upstream HTTP/SSE pipeline, with per-turn authority checks and platform-specific pressure limits.
2. **Security-sensitive provider effects are fenced by identity.** Codex credential updates use row incarnation, owner/provider/account identity and credential revision rather than a late unrestricted state write. Catalog coordination and affinity execution reuse those authoritative boundaries. Affinity carriers bind key/owner/domain and companion data; unsupported or corrupted required state fails closed. Setup exchange additionally consumes a scoped, short-lived, single-use lease atomically against current authority and key revision.
3. **Protocol changes preserve failure and identity semantics.** The reviewed translators reject unrepresentable opaque/tool constraints instead of silently flattening them, preserve refusal/reasoning distinctions and progressive usage, and avoid treating missing terminal events as success. Lite conversion is request-local, collision-checked and reversible at canonical observation/persistence boundaries; Fast accounting uses the executed raw model and selected tier rather than a guessed public-model multiplier.
4. **Transport and diagnostic changes have explicit resource limits.** Raw HTTP lifetime covers early responses, upload producer failures, cancellation and concrete socket close. Retry waits for body cancellation and backoff. Capture is opt-in, bounded and lazy; export uses a conservative metadata projection. New dump/catalog/setup schema changes use additive numbered migrations and fenced cleanup/adoption operations.
5. **Adoption decisions use measured tradeoffs.** Native prepare-once and bounded hashing were separated from the unadopted production JSON-snapshot selection. The D08 projection candidate was rejected despite a passing oracle because whole-load cost regressed. The documentation preserves negative results and identifies synthetic/local versus live/deployed evidence.

### Minor (nonblocking follow-ups)

#### M1 — Reorder reconciliation outlives the UI and retries without backoff

- **Files:** `vnext/apps/dashboard/src/state/reorder-upstreams.ts:151-181`; `vnext/apps/dashboard/src/state/upstreams.ts:23-35,48`.
- **Trigger:** an order rebalance applies at least one patch, a later patch fails, compensation also fails, and the authoritative reload continues to fail. The `for (;;)` reload loop retries every second and calls `onError` on every failure. Unmount only removes the snapshot subscription; it does not stop this controller's polling or toast/reload callbacks.
- **Impact:** repeated background requests and notifications after leaving the tab, with queued intents retained indefinitely. No new authorization bypass or demonstrated order-data loss follows from this observation.
- **Recommendation:** introduce a recoverable reconciliation lifecycle with capped backoff, notification deduplication and UI disposal handling. Preserve pending intents or explicitly expose their unresolved state; simply dropping the queue on unmount would weaken the existing recovery contract.
- **Disposition:** introduced UI lifecycle debt, already carried by D06; nonblocking for local integration.

#### M2 — Native failed-turn test title overstates its recovery contract

- **File:** `vnext/apps/platform-cloudflare/src/responses-websocket.workerd.test.ts:296-320`.
- **Trigger/evidence:** the test waits for `response.failed`, opens a second socket and asserts a successful full request there, then manually terminates both sockets in `finally`. It never observes the first socket's close before cleanup, despite the title saying it closes.
- **Contract check:** `vnext/packages/gateway/src/data-plane/chat-flow/responses/session.ts:247-251,269` clears failed local state and permits return to idle after cleanup. `session.sqlite.test.ts:428-443` explicitly tests a full fresh request on that same connection. The F4 brief and pinned client acceptance require fresh-connection recovery, not an unconditional gateway-initiated close after every failed terminal.
- **Impact:** the title can mislead future reviewers into believing server-initiated close is tested or required. The current assertions accurately prove failure plus a full request on a new connection; they do not establish who closes an old socket.
- **Recommendation:** rename the test to its actual failed-turn/fresh-connection recovery assertion. Do not add an unconditional close assertion or change session behavior without an explicit contract change. A separate client-driven-close test may be useful if that client behavior is the intended subject.
- **Disposition:** introduced test-description issue, nonblocking; no product close failure established.

#### M3 — Explicit token coalescing scope can hide a different mint guard

- **File:** `vnext/packages/provider-codex/src/access-token.ts:114-142,173-174,245`.
- **Trigger:** two no-signal calls use the same credential and explicit `coalescingScope` but different `beforeMint` callbacks. The flight key contains `scopeNumber(coalescingScope ?? beforeMint)`, so the second callback is not independently represented in the key and can share the first guarded mint.
- **Impact:** an API composition hazard for future callers that expect both guard identities to matter. The current gated production callers pass no explicit scope; signalled calls do not take this shared-flight path. I found no active production authorization bypass from this combination.
- **Recommendation:** bind both scope and guard identities in the key, or explicitly disallow their simultaneous use before adding such a caller. Add a focused two-hook regression then.
- **Disposition:** latent API contract issue, nonblocking for the current call graph.

#### M4 — Some accepted regression evidence remains weaker than its durable test coverage

- **Files:** `vnext/packages/provider-llm/src/__tests__/json-body.test.ts:1-113`; `vnext/docs/superpowers/research/2026-09-29-json-body-evidence/review.md:14-18`; `vnext/apps/platform-bun/src/__tests__/responses-websocket.test.ts:55`.
- **Evidence:** the serializer bundle retains benchmark/workerd scripts, but its own review still describes the named listener-removal, genuinely pending-read, no-prefetch, generator-failure and all-32-control-character checks as reviewer probes. The normal JSON-body tests do not assert all those boundaries. Bun's native normal-suite test principally covers warmup/continuation; representative pressure, abrupt-disconnect, durable and private cases remain broader in retained acceptance scripts.
- **Impact:** future regressions can evade the ordinary CI selection even though the recorded isolated checks passed. Workers now has ordinary native protocol/abort/output-budget tests, and shared session tests cover durability/private authority, so the earlier coverage concern is partly resolved.
- **Recommendation:** promote a small representative subset into normal CI or preserve the exact standalone lifecycle probes in the evidence bundle. Do not replace real pending-read assertions with a read already synchronously fulfilled before abort.
- **Disposition:** coverage durability improvement; no current functional failure inferred.
