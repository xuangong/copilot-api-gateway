# C08 authorized import, reimport and explicit refresh

Status: implementation frozen for root review at accepted base `607b2290f67ce8e7d054cce4ddf9eb3ad13d2d10`. The exact product file list and SHA-256 map are in the matching `-owned.json` and `-frozen-sha256.json` files. No commit, push, deployment, real credential or live account was used.

## Delivered behavior

- Session-authenticated `POST /api/upstreams/codex/preview` accepts `{ document }` and returns `{ candidates }`. It streams at most 1 MiB of HTTP body before JSON materialization, retains original source indexes, reports fixed parser issues for invalid candidate rows and performs no persistence or OAuth. These three credential-management POST paths skip unrelated best-effort Copilot prewarming while retaining authentication.
- `POST /api/upstreams/codex/import` reparses the submitted document and selected `sourceIndex`. New import accepts `{ document, sourceIndex, name, ownerId?, enabled?, sortOrder?, flagOverrides?, disabledPublicModelIds?, proxyFallbackList? }`, creates only with `createIfAbsent`, and returns `201 { upstream }`. Admin owner selection follows existing session semantics; ordinary users cannot assign another owner. Same-account reimport accepts only `{ document, sourceIndex, upstreamId }`, retains row identity, installation ID, name, flags, filters, order/enabled and proxy policy, and returns `200 { upstream }`. Its credential replacement uses the accepted CAS operation and advances catalog generation once. Identity, revision, owner/incarnation and provider changes fail rather than replaying an old credential. Retries are bounded to eight.
- `POST /api/upstreams/:id/credentials/refresh` accepts an owned renewable Codex row only. It captures authorized row identity and configured egress before minting, carries the request cancellation signal into the accepted credential lifecycle, and returns an authoritative public reread. Invalid proxy configuration fails closed; canceled or late OAuth results cannot write a replaced row. Nonrenewable credentials retain their bearer and receive a safe client error.
- The existing Upstreams dashboard now creates Codex rows by pasted/file JSON and account preview, supports same-account reimport from the edit form, and offers explicit refresh only for renewable rows. It shows public credential health, renewable/access-only status and known/unknown expiry. Raw JSON stays in modal memory and is cleared on success/cancel/unmount; changed document/target or newer requests invalidate stale async results. Existing metadata editing remains available. Both languages have matching UI text. Parser placeholders on invalid rows are not shown as confirmed expiry or renewability.
