## B08 measured capacity and lease decision

The existing implementation in `gateway/src/responses-maintenance.ts` deletes four batches of at most 100 rows, with expiration preferred before disabled/deleted-key cleanup. Every selection and deletion is a single `DELETE ... WHERE response_id IN (SELECT ...) RETURNING` statement. The Bun server ticks every 60 seconds with an in-process overlap guard. CFW `wrangler.jsonc:11` also schedules every minute. Existing tests cover 450-row drain, renewal, disabled keys and orphans.

A fresh synthetic probe used the actual Bun SQL adapter, repository schema and sweep function against `:memory:` on Bun 1.3.0. It inserted 10,000 expired rows plus one active row. Two sweeps launched with `Promise.all` left 9,201 rows (800 deleted). Continuing to drain required 25 total sweep calls, left exactly the live row, and took 13.70 ms overall. This is an in-process SQLite logical concurrency/capacity check, not two processes, D1 latency, production load, or heap measurement.

Capacity is **400 rows/minute per single scheduler**, or **24,000 rows/hour**, so a 10,000-row static backlog takes 25 ticks (about 25 minutes, depending on the initial tick). Sustained expiration arrival above 400/minute grows the backlog; an expiration stream saturating the budget can starve disabled-key cleanup. Average new snapshot rate is not automatically the expiration arrival rate because retention renewal shifts deadlines.

Recommendation: do not add a cross-instance lease for correctness. The current atomic idempotent SQL deletion has no external file side effects and duplicate schedulers merely compete for remaining rows; the probe preserves the live row. A lease would reduce duplicate query cost but not improve draining capacity and could make cleanup less available. If actual D1 contention warrants coordination, measure it first and use a leased time/row budget, not an unconditional lock. The useful bounded enhancement is counters/remaining-backlog observability plus a fair budget between expired and inactive rows; raise the budget only against row/CPU query measurements. B07 external file deletion is a separate coordination problem.
