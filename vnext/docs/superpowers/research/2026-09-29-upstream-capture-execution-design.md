# D02 execution slices: bounded application HTTP attempts

Read-only design, 2026-09-29. No product edits, tests, commit, deployment, or live configuration changes were made for this note. D02 is an optional extension of an opted-in key's existing request dump. The current migration tip is `vnext/packages/gateway/migrations/0015_dump_maintenance.sql`; use the next free numbered migration (currently 0016) and recheck the tip immediately before implementation. B05's bytes-path retry cleanup is in `46aacfac`. The b2/c2 replay adapters are deferred and are **not** D02 prerequisites. Native provider `string` bodies should use the separately prepared bounded UTF-8 capture seam; do not re-encode a full body merely for diagnostics. Slices 1 and 2 are independently verifiable foundations; neither claims that production request capture is active before Slice 3.

## Invariants shared by all slices

- Capture the HTTP adapter's `fetch-body` representation before protocol parsing. Runtime `fetch` may already have decompressed it. Do not describe it as TLS, HTTP/2 framing, compressed socket wire bytes, or proof that buffered request bytes were sent.
- Per dump: at most 8 recorded transport attempts, 64 KiB request prefix and 256 KiB response prefix per attempt, 1 MiB total retained body bytes, 16 KiB combined headers per attempt, and an independent 64 KiB total metadata/header budget. Count budgets in bytes. Continue forwarding/counting after caps and mark truncation; capture exhaustion never rejects inference. Track omitted attempt count separately and boundedly. One giant chunk must contribute only the copied prefix, never retain its whole backing buffer.
- Each recorded transport attempt needs a stable request-local ID, parent outer-call ID, upstream ID, order, relative timestamps, method, sanitized URL/operation label, sanitized request/response headers, nullable status, `fetch-body`, observed/captured byte counts, explicit truncation, and terminal state `eof | cancelled | read_error | fetch_error | not_consumed`. Keep request `prepared` bytes distinct from actual transport writes. A response total is exact only at EOF; cancellation/error/never-read leaves total `null`, while observed-so-far stays available. Capture terminal state is independent of HTTP or protocol success.
- An inline pull-through response stream observes only consumer pulls. It never tees to an independently draining branch. Forward cancel to the original reader and release locks on EOF, error, and cancellation. A discarded 429/500 body may have an empty cancelled prefix; never drain it to improve the dump. Snapshot bounded state and close still-open observers as incomplete when the logical request finishes or cancels. Opaque single-use request streams must not be read for capture. A later B05b replay body can be observed by wrapping each `open`, without taking retry ownership; do not implement that adapter here.
- An opted-out key allocates no collector and adds no response wrapper. Collector, sidecar, SQL, file, or broker failures cannot turn a successful model response into a failure. Keep existing canonical client `ProtocolFrame` capture and downstream response behavior unchanged.
- **Redact before persistence and before creating the sidecar file.** Treat arbitrary upstream header names/values and every URL component as possibly credential-bearing. Persist only a small explicit allowlist of normalized metadata (for example, a validated media type without parameters and a validated numeric length); record omitted markers/counts. Do not persist raw `Authorization`, cookie, proxy/account/custom credential headers, URL userinfo, hostname, path, query, or fragments by default. A provider-supplied fixed operation label is safe; an unknown/custom path is `url_omitted`, even if its header/query names look harmless. Store only enum-like error categories, never raw exception messages. Detail API owner scoping is necessary but insufficient because a downstream key owner may not own the shared upstream credential. The redacted export must not regain raw fields.

## Slice 1 — collector and one sidecar (independently testable foundation)

**Owned product scope:** new `vnext/packages/gateway/src/shared/dump/upstream-attempts.ts`; focused edits to `shared/dump/{types,wire,store-contract,accumulator}.ts`, `repo/{dump-store,dump-maintenance}.ts`, one new numbered migration, and dump-specific tests (`dump-store.test.ts`, `dump-accumulator.test.ts`, new collector tests, `dump-maintenance.test.ts`, `migrations.test.ts`, owner-scoped detail/export tests only where the wire shape changes). Do not edit dial, providers, dashboard, canonical frame reducers, or replay contracts in this slice.

The pure request-scoped collector exposes begin/observe/finish and a bounded immutable snapshot. The sidecar is a versioned `upstreamExchanges` envelope in **one gzip spilled file per dump**, referenced by a new nullable `dump_records.upstream_exchanges_descriptor`. It may contain an empty `attempts` array for a newly captured request with no transport call. A legacy `NULL` descriptor decodes to **capture unavailable**, not proof of zero attempts. The read and wire types preserve this distinction. Encode binary prefixes losslessly (base64 on JSON wire); invalid UTF-8 is not repaired into text. The redacted export either omits these prefixes or supplies only explicitly safe aggregate fields.

Stage all applicable file keys before puts; write files before inserting the row; publish broker metadata only after row and all referenced files are committed. Treat sidecar as optional: if its own preparation/put fails, retire its stage and write the original dump with a null descriptor when possible; if a core dump write fails, preserve today's best-effort inference behavior. Extend the B07 caught-failure tombstone repair for the new key. Never create a row referring to an absent file; if a future/recovery path does commit a row before a file failure, delete/retire that row before publish and preserve the existing detail 409 behavior for externally missing referenced files. No SQL/file atomicity claim.

The migration must add the nullable descriptor, its expression index, a third arm in `dump_file_references`, `dump-upstream` in the collector's partial index and both code allowlists, an insert guard matching staged owner/key, an adopt trigger, a delete-retire trigger, and an update guard for immutable descriptors. Keep the existing REPLACE guard. B07's claim/ref check and 100-candidate bounded scan must see this third descriptor; owner key remains `(key_id, record_id)`, file keys stay under `dumps/v1/`. Do not edit migration 0015 or widen collection to unrelated file owners. Staging grace, late put after collection, claim token fencing, idempotent external delete, row-first/file-failure recovery, retention expiry, disabled/cleared/deleted-key histories, and independent maintenance-task failure handling remain intact.

**Acceptance:** pure collector tests at exact cap and one byte over for every budget, one huge chunk, many tiny chunks, binary invalid UTF-8, complete/malformed SSE bytes before parser, no-body, fetch/read error, never-read, cancellation and lock release, plus two interleaved collectors with no cross-owner data. Real temporary SQLite + temporary `FileProvider` tests prove legacy null compatibility, stage/put/insert/publish ordering, optional sidecar failure, pre-row failure repair, late stage collection, deletion/expiry, referenced-file protection and claim races. Verify migration corpus on Bun SQLite and local D1 syntax, gateway typecheck/purity, and the focused dump suite. No live data operation.

## Slice 2 — generic dial attempt observer (still disabled by default)

**Owned product scope:** `vnext/packages/dial/src/{fetcher,index}.ts`, its focused `__tests__/fetcher.test.ts`, and only the small generic observer type/export needed by that package. If a shared type is required, keep it in `@vibe-core/dial` or a lower framework package; it carries generic method/status/byte/terminal callbacks, never imports gateway dump types. No gateway/provider activation, no raw proxy transport rewrite, and no b2/c2 replay adapter.

An optional dependency-injected observer begins one outer call on each observed `Fetcher(url, init)` invocation. Each actual `runProxied`, `runDirectConnect`, or `runDirectFetch` dispatch, including second-pass and implicit final direct-fetch fallback, begins a child transport attempt linked to that call ID. Missing proxy configuration or failed body materialization before a transport call is a parent pre-dispatch failure, not a fabricated transport child; do not claim request bytes were sent. A returned response body is wrapped at the transport child boundary with the Slice 1 pull-through contract, so provider HTTP retries and fallback statuses retain separate attempts. Avoid duplicate body retention at the parent call; the parent is grouping/ordering metadata. The observer callback path is best effort and must preserve dial fallback/backoff and abort semantics. With no observer, retain the existing fast path and allocation behavior.

Native `string` request bodies use the prepared bounded UTF-8 prefix and byte count. A `Uint8Array` copies only the allowed prefix. Already-materialized byte bodies can be labeled `prepared`; direct-fetch-only Blob/FormData/opaque streams stay `unobserved` unless their bytes are already safely available. Never materialize an opaque body solely for dumping. Do not infer sent bytes from a prepared buffer or a call that failed before socket dispatch.

**Acceptance:** dial unit tests enumerate explicit and implicit fallbacks, proxy backoff passes, thrown fetch, abort, no-body response, and status/body cancellation. Assert child IDs/order and parent association, lock/cancel behavior, no extra reads, no dispatch-semantic change, bounded native multibyte UTF-8 at the byte boundary, and zero callbacks on the no-observer path. A successful outer fetch alone must not be reported as every actual transport attempt if the inner hook is absent.

## Slice 3 — generation-only request wiring and end-to-end proof

**Owned product scope:** `vnext/packages/gateway/src/data-plane/{dial/per-request.ts,providers/registry.ts,routing/{binding-resolver,candidates}.ts}` and the existing execution call sites that pass the current dump into binding/dispatch (chat completions, messages, Responses/Gemini, count tokens, embeddings, images, alpha search, and any orchestrator call using that binding). Use a narrow optional execution-fetcher seam in `vnext/packages/provider-llm/src/plugin.ts` and the terminal HTTP call sites of the six installed providers (`provider-{copilot,custom,azure,codex,claude-code,sdf}`) only as needed to keep discovery/auth on their ordinary fetcher. Own corresponding registry/dispatch/provider integration tests. Do not alter unrelated control-plane probes or model catalog behavior.

Pass the current dump's observer explicitly through binding resolution into each per-request provider/fetcher; never use a process-global or async mutable `currentDump`. Build ordinary fetchers for `getCachedModels`, background catalog refresh, OAuth/session exchange, token refresh, passport, usage probes, and control-plane upstream probes. Only the provider's **terminal application HTTP call** receives the observed execution fetcher. Thus a Copilot 401/403 generation retry and a shared HTTP 429 retry each create separate outer call IDs, while the intervening credential refresh creates none. An observed outer call delegates to Slice 2, whose child records are the actual proxy/direct attempts. For the request-token Copilot fallback (no stored upstream row), use a request-scoped observed direct fetcher with a noncredential logical upstream ID. Unknown or unmarked calls are excluded rather than guessed from URL shape or broad `provider.fetch` timing.

The existing `openDumpAccumulator`/`openRequestDump` retention decision gates observer creation. Bindings can be constructed before a winner is selected, but only selected execution terminal calls can emit attempts. Finalization snapshots the collector alongside the existing dump write; an open child becomes incomplete without waiting forever. Gate all callback/storage errors away from the inference result. Expose the safe envelope through the existing owner-scoped detail wire; no dashboard UI is necessary to satisfy D02. A later UI task can consume this wire if requested, without changing the capture or storage contract.

**Acceptance:** real registry/dispatch plus dial tests show separate 401 refresh, 429 cleanup/retry and proxy fallback records; the rejected 429 body may be empty/cancelled and is never drained. Test discovery and OAuth during and outside execution scope produce no attempt; test simultaneous requests for two different owners, retention-off with no collector/wrappers/sidecar, custom credential header and URL userinfo/query/path tokens never reaching the sidecar or detail response, and all supported execution endpoint families. Verify observed/captured totals and final terminal states when the parser consumes complete and malformed SSE, when it never reads, and on caller cancellation. Run focused gateway/dial/provider tests, package typechecks, purity checks, and then the normal clean CI/integration gates; report exactly which environments were exercised. No deployment is implied.
