# Raw replay transport acceptance

This slice adds a neutral replay body and response-owned raw HTTP upload lifetime. It does not adopt provider JSON replay or streaming runtime fetch.

The loopback fixture uses real Bun sockets and the existing userspace TLS implementation. A peer stops reading a 100 MB upload and sends an early 200 or 413 with a delayed response tail. Each of the four TCP/TLS combinations must preserve `early-tail`, cancel the source once, close once and release the writer. Generated bytes depend on kernel buffering and scheduling and are not a memory-allocation bound. TLS verification is bypassed only for this self-signed loopback fixture.

Run `accept.ts` with Bun and set `B05_TLS_FIXTURE_DIR` to an isolated directory containing `local-key.pem` and `local-cert.pem` generated with OpenSSL for localhost. Never use live credentials. The script uses ephemeral loopback ports. `root-accept.out` records root's clean-tree run. Deterministic product tests separately cover blocked reads/writes, exact length, framing, producer failures, consumer cancellation and caller abort after headers.

Bun/Workers native fetch adapters, higher-layer retry classification and provider adoption remain separate tasks. No live upstream, deployment, Workers raw socket or production proxy verification is claimed.

## Runtime defect found during acceptance

The first clean-tree run passed, but the fix1 rerun stalled in the first plain TCP case with no completed result. Root terminated the isolated fixture after preserving its process sample (exit 143, not a passing run). Phase instrumentation then confirmed status 200 and the delayed tail had arrived and concrete socket close completed, while response consumption still waited for upload settlement. Write-callback instrumentation observed 167 client writes but only 166 callbacks after socket close. Installed Bun 1.3.0 did not settle one pending write callback on destroy in that run. This justified a narrow Bun adapter follow-up to settle tracked pending writes on terminal socket events; passing deterministic tests alone did not establish this actual-runtime gate.

## Raw API capability

Direct `fetchOnStream` callers must supply a concrete `closeTransport` callback that initiates interruption of pending transport operations. Both existing production routes already supply it. Missing callbacks now reject before I/O; independently canceling a Web Streams readable cannot guarantee interruption of its writable's in-flight sink write. This is an explicit source/API compatibility change for direct consumers.

After the Bun pending-write fix, root ran the complete TCP/TLS × early 200/413 matrix three times on the clean verification tree. All 12 cases passed and exited normally under an external 10-second watchdog. `root-results.json` contains concise result records; `root-accept.out` retains the complete successful diagnostic output. The earlier hang is retained above and in `hang-diagnosis.md`, rather than erased by the successful rerun.

Final validation: initial and two scoped independent reviews passed after fixes. Clean `bun run ci:local` passed 4,250 tests with one existing skip and zero failures; all typechecks, framework purity, lint (36 inherited warnings, zero errors), dashboard build and Workers dry-run passed. No deployment was performed.
