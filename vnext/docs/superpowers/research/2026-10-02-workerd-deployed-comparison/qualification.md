## Inspector root cause

The installed Miniflare implementation only creates its Inspector proxy when that option is enabled. This harness uses direct workerd Inspector access. The initial selector incorrectly expected the proxy path `/<worker-name>`; the actual direct target is `core:user:<worker-name>` with socket path `/core:user:<worker-name>`. Thus the canary failed closed at the measurement interface after successful ordinary product requests.

The correction `5f601c6e092986160856eb9f0d320a6ef9091d02` preserves exact ID/path/host matching, rejects unrelated or ambiguous targets, and retains discovered target identities. It does not enable the proxy or change ordinary latency runtime configuration. Focused tests passed (26 pass / 0 fail / 96 expectations), strict typecheck exited 0, and scoped independent review passed. The separate Canary 03 subsequently verified actual A/B attachment and commands under a new frozen identity. Formal collection is separate from this qualification.
