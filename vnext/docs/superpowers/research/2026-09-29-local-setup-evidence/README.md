# Local setup acceptance (D10B)

This evidence uses synthetic accounts, real D10A single-use leases, and isolated temporary client homes. It never configures a live Claude/Codex installation or changes account login files. D10A authority/atomic exchange evidence is retained separately in `../2026-09-29-setup-lease-evidence/`.

## Scope and limits

The public runner requires **preinstalled Bun**. POSIX shell and PowerShell wrappers were exercised on macOS. Native Windows ACL, filesystem, and console behavior remains unverified. The runner checksum detects transfer/build mismatch, not a compromised server. Digest checks and a cooperating lock are not an OS-level compare-and-swap against arbitrary concurrent writers. Custom client homes are rejected before lease exchange.

The suite covers both clients through direct CLI, sh and macOS PowerShell; opaque model strings; configuration preservation and untouched auth.json; private command-auth credentials; dry-run/cancel/malformed configuration; rejected custom homes with an unconsumed lease; actual OS SIGKILL and separate-process journal recovery; concurrent-edit preservation; helper permission/missing-file failure; copied-command error handling; authenticated browser preview/mint/revoke/remint and late-response/assignment boundaries; and actual workerd/D1 static asset parity. All source/runtime/browser outcomes are recorded separately from performance claims.

The native client harness uses the first-party Codex source pinned at `8ff74cc9b11ac54c4c4446ef60a87b49ae657a1f`. It parses the actual generated provider with Codex's native schema and invokes its installed Bun helper for a real Authorization header to a loopback HTTP responder. It intentionally substitutes the local HTTP transport; accepted C12 evidence covers WebSocket interoperability. It does not start an agent. The opt-in normal test also parses configuration with locally installed Codex 0.159.0 (`features list`).

## Reproduction

Build assets from the candidate checkout first (`bun run build:ui` in `vnext/`). Set `VNEXT_PROBE_ROOT` to the absolute repository root. Copy `fixture.ts.txt` into a temporary `.ts` file and start it with Bun. It prints a JSON record and writes `state.json` under its owned temporary directory. Keep this host in a separate process and use the emitted state path for the following sequential commands:

```sh
bun cli.mjs /temporary/server/state.json
D10B_WRAPPER=posix bun cli.mjs /temporary/server/state.json
D10B_WRAPPER=powershell bun cli.mjs /temporary/server/state.json
bun contract-rejection.mjs
bun failures.mjs /temporary/server/state.json
node browser.mjs /temporary/server/state.json
```

PowerShell probes require `/usr/local/bin/pwsh` on this measured host; adjust the scratch harness path for another host without calling that native Windows evidence. `browser.mjs` supports `D10B_PLAYWRIGHT_MODULE` pointing to an installed Playwright ESM module with Chromium installed. Browser-created leases are revoked after assertions. Scripts retain only synthetic temporary fixtures; stdout contains test metadata, not production credentials. Stop only the fixture PID printed by this run when done.

Run `node workerd-assets.mjs` with the same `VNEXT_PROBE_ROOT` after the Bun fixture exits. It builds the adjacent Worker template with the actual product entry and creates/migrates an isolated D1 database using the installed locked Miniflare/Wrangler versions. It verifies all four public assets against generated bytes, response headers, and 404s for prototype/unknown/query names.

`native-codex.sh` takes the temporary installed Codex home parent reported by the direct CLI probe. Set `D10B_CODEX_FIXTURE_ROOT` to an isolated Codex fixture containing `source/codex-rs`, populated offline cargo cache and build target from the pinned source. Copy `client_d10b_setup.rs.txt` to `core/tests/suite/client_d10b_setup.rs` and add `#[path = "client_d10b_setup.rs"] mod d10b_setup_acceptance;` to `core/tests/suite/client.rs`. The script runs only that explicit ignored test, under the temporary HOME. Its retained log may contain the pinned tree's inherited unused-import warning.

## Review follow-up

The initial complete CI and seven runtime probes passed, but independent review found two uncovered boundaries. Valid-digest arrays passed coercive enum/header validation; old custom-header credentials appeared in the nominally redacted local diff. `contract-rejection.mjs` independently reproduced both before their fixes. The fix also covers copied command failure status and retained recovery diagnostics. Initial green checks are not used to dismiss these findings.

Final result counts and the accepted revision are recorded in the accompanying acceptance report after the scoped re-review. Remote CI, Docker image construction, deployment, production homes and native Windows are outside these local evidence claims.
